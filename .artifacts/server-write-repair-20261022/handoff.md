After deferred effects finish, it reads actual committed images under the same writer and prior authoritative row state, preserves first-touch order and exact codecs, and applies final-image limits before history publication. - Go and Kotlin stage complete intended business images and preservation decisions, discover plain/composite unique dependencies using validated physical codecs and SQLite collations/NULL semantics, prepare an acyclic prefix durably, and vacate only cyclic components plus their staged FK closure. Unsupported indexes, unsafe temporary-deletion effects and conflicting final images fail atomically. Snapshot installation uses the complete desired set after clearing old managed rows. Settlement/replay and conflict owners share the mechanism; original metadata decisions still publish exactly once. Main/temp schema versions invalidate retained derived graphs after application index/trigger upgrades.
- Typed blockers carry bounded reason codes and exact operation/table/index/trigger/key diagnostics. A blocker never auto-resolves conflict or advances the checkpoint. Supported valid transfers/cycles apply automatically.

## Developer recovery

For an unsafe trigger or unsupported index, correct the identified schema through the application's supported upgrade path and retry ordinary sync. For competing pending records, use supported application edits or conflict-resolution APIs. A retained invalid server bundle cannot be fixed by appending another server write: correct authoritative current state and use supported Rebuild/rebuild snapshot recovery under its existing admission checks. Pending/frozen operations are never discarded to force recovery; their schema or conflict may need correction first. Never edit _sync_* rows, skip a checkpoint manually or delete a database to bypass a blocker.

These are fresh-database changes. Separately authorized setup should provision an empty application PostgreSQL database with current business schema, bootstrap this server, then create new client databases with current SDKs/generation. No old-format migration or repair of historical stale/ghost capture is included. Detailed behavior/setup is also recorded in docs/documentation/server-originated-writes.md.
